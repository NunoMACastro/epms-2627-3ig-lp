# Linguagens de Programação · 12.º IG

Materiais da disciplina de Linguagens de Programação do 12.º ano do Curso
Profissional de Técnico/a de Informática de Gestão.

Este repositório contém os materiais já preparados para as aulas. Um guia pode
ser publicado antes de ser dado nas aulas: podes lê-lo à frente. Se um guia
ainda não está aqui, é porque ainda não foi preparado.

## Organização

Os materiais estão agrupados por percurso, pela ordem em que a matéria começa a
ser dada. A tabela diz também a que módulo do programa corresponde cada área,
para quem precisar do código oficial.

| Pasta | Área | Módulo |
| ----- | ---- | ------ |
| `01-acesso-a-dados/` | Acesso a dados: servidor, API e base de dados | M14 |
| `02-reporting-e-documentacao/` | Relatórios de gestão e documentação técnica | M15 |
| `03-distribuicao-e-suporte/` | Qualidade, distribuição e apoio ao utilizador | M16 |
| `04-projeto-final/` | Projeto final: a tua aplicação | M17 |

Cada pasta de área tem um `README.md` com o índice dos guias publicados.

Além das áreas há três pastas de topo. O código de exemplo, que se lê para
perceber uma ideia, fica em `exemplos/`. O código de partida dos laboratórios,
que está incompleto de propósito e é para trabalhares em cima, fica em
`laboratorios/`. Os enunciados de avaliação já divulgados ficam em
`avaliacoes/`. Os instrumentos do projeto final, quando existirem, ficam em
`projeto/`.

Nenhuma destas pastas é criada antes de ter conteúdo real. Se não a vês, é
porque ainda não há nada lá dentro.

## Como são os nomes dos ficheiros

Os nomes seguem sempre a mesma regra, para que seja possível encontrar um
material sem procurar:

- Em português, tudo em minúsculas, sem acentos, com hífen entre as palavras.
- O número no início é o número do tema dentro da área, pela ordem em que é
  dado. O guia `04-api-express-e-contratos.md` é o quarto tema dessa área.
- Os números não são contínuos: se faltar um número, é porque esse tema ainda
  não tem guia publicado.
- Cada tema pode ter até três documentos com o mesmo número: o guia, para ler e
  estudar; o laboratório, ao lado dele, com o mesmo nome e o sufixo
  `-laboratorio`, para seguir passo a passo no computador; e a ficha de
  exercícios, também ao lado, com o mesmo nome e o sufixo `-exercicios`, para
  praticares sozinho.

Exemplo da estrutura de uma área, com os ficheiros que a primeira tinha quando
este exemplo foi escrito:

```text
01-acesso-a-dados/
├── README.md
├── 02-modelo-documental-e-consultas-no-atlas.md
├── 02-modelo-documental-e-consultas-no-atlas-laboratorio.md
├── 02-modelo-documental-e-consultas-no-atlas-exercicios.md
├── 03-arquitetura-e-setup-node.md
├── 03-arquitetura-e-setup-node-laboratorio.md
├── 03-arquitetura-e-setup-node-exercicios.md
├── 04-api-express-e-contratos.md
├── 04-api-express-e-contratos-laboratorio.md
└── 04-api-express-e-contratos-exercicios.md
```

## Como usar

Cada guia é feito para ser lido antes de se escrever código: primeiro a
explicação, depois um exemplo completo, e no fim os exercícios. Tenta prever o
resultado de cada exemplo antes de o correres. É aí que se percebe se a ideia
ficou mesmo entendida.

As resoluções dos exercícios não estão neste repositório. São trabalhadas na
aula, porque um exercício só ensina enquanto ainda não tem resposta à vista.

Todo o material necessário a um guia está neste repositório. Se alguma coisa
faltar ou estiver errada, avisa na aula.
